# AtSpMV 优化与消融报告

本报告记录 2026-11-11 扩展前的优化和消融。后续已将分组布局推广到六种普通 shape，当前接口与新结果见 [六种 shape 扩展测试](grouped-columns-six-shapes.md)；下文只支持 32×1 的描述及数字对应扩展前版本。主线是 **减少填充 → 匹配线程与行长 → 控制长尾 → 降低索引和执行开销 → 按场景选型 → 在应用中复用**。各项收益不可相乘；不同后端、硬件、样本和计时范围的数字分别报告。

## 1. 新布局是什么，是否只能用于 32×1

“新布局”是 **按列索引编码宽度分组的 AtBSR 布局**，不是混合 tile shape，也不是把 X 放入共享内存。计算仍使用 CUDA Core FP64 乘加。

原 AtBSR tile 有 32 个槽，保留每个槽的列号。旧逐 tile 压缩按列号跨度，将一个 tile 编码为 `base + uint8/uint16 偏移` 或 int32；计算时逐 tile 读取元数据，判断编码并定位变长数据。新布局先把每个 32 行组的 tile 按编码分成三段，对应全局的三个定长索引池；数值按同样的顺序重排：

```text
同一行组原 tile 顺序：T0(8位), T1(32位), T2(8位), T3(16位)
索引池：uint8[T0,T2] | uint16[T3] | int32[T1]
数值区：FP64[T0,T2] | FP64[T3]   | FP64[T1]
行组元数据：三个区间；窄索引 tile 另有基准列号
计算：分别执行三个固定类型循环 → 寄存器累加 → 写回原行号
```

例如一个 tile 的列号在 1000–1200 范围，可保存基准 1000 和 32 个字节偏移。原 128 字节列号变为 32 字节偏移加基准及分摊元数据；FP64 值仍为 256 字节，因此列索引减少 75% 不等于总矩阵流量减少 75%。当前分类使用跨度 `<255`、`<65535` 两个保守界限。

**当前实现只支持普通、非 balanced 的 32×1，且原列索引为 int32、非空、索引规模未溢出、计入区间/基准后仍省空间。** 已有 int16、其他 shape、balanced 或不省空间时回退。32×1 是实现限制，不是压缩原理的限制：推广到其他 shape 需要实现对应的 lane 分工和行内归约；推广到拆分任务还需要重新定义任务区间及部分和合并，不能只删资格判断。

实现见 [groupedTileColumns.cuh](../include/detail/groupedTileColumns.cuh)：`groupTileColumns` 分类/扫描/重排，`groupedTileSpmv` 计算。`SpmvPlanOptions.group_tile_columns` 默认关闭，与旧 `compress_tile_columns` 互斥。它保留 tile 数与槽数，不改善 `nnz/(32×tile数)` 密度，只压缩索引并改变访问路径。可选数值更新映射还会增加常驻空间。

## 2. 当前优化手段清单

| 层次 | 手段与作用 | 代码/状态与边界 |
|---|---|---|
| 表示 | 按行长排序，将相近行分组，减少 padding | `src/atspmvProduct.cu`；recorder 恢复输出行序 |
| 表示 | 六种 32 槽 shape：1×32、2×16、4×8、8×4、16×2、32×1 | 同上；影响密度、行内线程数、归约和任务数，不是 Tensor Core shape |
| 调度 | balanced 拆分长任务，每任务默认最多 8 tile，原子合并 | 同上；多出清零/原子成本，支持 cap 4/8/16/32 |
| 指令 | 批量预取、不同比例的独立累加链 | `include/tunedSpmv.cuh`；depth 1/2/4/8，可选，库默认 depth=0 使用原内核 |
| 调度 | CTA 内合并相同行组部分和，减少全局原子数 | 同上；可选，仍可能跨 CTA 原子合并，不保证更快 |
| 调度 | 调整每 CTA warp 数、每任务 tile 上限 | `include/kernelConfig.h`；可选，改变 occupancy/任务开销，不能统一增大或减小 |
| 执行 | 普通模式直接覆盖 y，beta=0 时省去冗余清零 | `src/atspmvProduct.cu`；balanced 仍需清零 |
| 索引 | 小列维度自动采用 int16 列号 | 同上；严格条件 ncols<32767，行指针不变，不是 FP16 数值 |
| 索引 | 旧逐 tile 的 8/16/32 位无损压缩 | `include/detail/compressedTileColumns.cuh`；可选，动态解码可能抵消带宽收益 |
| 索引 | 新的定长分组索引池及配套 kernel | `include/detail/groupedTileColumns.cuh`；可选，当前资格见第 1 节 |
| 表示/调度 | 不同行组混合六种 shape、特化循环及 balanced mixed | `include/detail/mixedTile.cuh`；减少槽数不保证性能，构建/维护成本额外存在 |
| 规约 | 长行由 cluster 多 CTA 分片，通过 DSM 与 mbarrier 合并；短行可融合 AtBSR | `include/dsmLongRow.cuh`、`src/spmvPlanDsm.cu`；Hopper 路径，非通用收益 |
| 后端 | CSR vector、不依赖 cluster 的两阶段归约、cuSPARSE 回退 | `include/detail/spmvPlanKernels.cuh`、Plan；避免为不合适矩阵强行转换 |
| 选择 | shape 时间模型、统一后端模型、可选初始化实测/有界精调 | `src/selection/`、`src/spmvPlan.cu`；候选覆盖与校准范围有限，非全局最优保证 |
| 复用 | Plan 复用布局/资源，固定 CSR 结构只更新值；调优可共享打包数据 | `include/detail/planValueUpdate.cuh`、Plan；数值更新本身要计时，结构改变需重建 |
| 应用 | MFEM 的 GPU 组装、隐式矩阵符号并集复用、GPU 数值更新 | `apps/mfem/`；对所有后端公平开启的通用应用优化 |
| 通用缓存 | X 的 persisting L2 窗口 | `apps/mfem/spmvOperator.hpp`；可选，对 cuSPARSE 同样适用，不算 AtBSR 专属贡献 |

CUDA Graph 用于减少重复调用的主机提交干扰并复用执行序列；本报告的内核时间是 warm Graph 口径，不把它当成 tile 独有收益。PDL、跨 cluster 的永久 X 缓存、Tensor Core、SpTRSV/SpMM 扩展不作为当前 SpMV 已验证优化计入。

## 3. 实验结构和控制

| 实验 | 目的 | 覆盖与证据 |
|---|---|---|
| A：本轮因子消融 | 分开比较 shape、拆分、预取、清零、索引、CTA 参数、mixed、DSM | GPU 3 H100 PCIe，9 个有意选择的已知矩阵，380 对候选实例 |
| B：本轮行排序 | 同一 host 打包方法、同一生产 kernel，只改变行顺序 | GPU 2 H100 PCIe，4 矩阵×2 shape；不与 A 的绝对时间混算 |
| C：历史矩阵布局对照 | 检查开启布局后是否保留原 shape 选择的优势 | 本日同卡复测 24 矩阵，另有 5 个事后独立复测 |
| D：已有应用/机制消融 | 区分结构复用、L2、压缩与完整应用；查看硬件计数 | MFEM 小/大规模的同轮对照和独立 CPU 参考，详见引用报告 |

A/B 均用 FP64、两个相反候选构建顺序、9 轮随机交错测量、3 轮预热，每个 Graph batch 连续 8 次 SpMV，以内部 event 计时。先取每进程中位数，再对配对时间比取几何平均。不计 CSR 读取、转换、候选搜索和 Graph 构建；没有 persisting L2，未锁时钟，进程监测不能排除所有短暂干扰。所有候选均检查两个非均匀 X 的直接结果和 Graph 结果，对照 CPU long double 全行参考。

A 有 6840 条有效计时、2280 次全向量检查；B 有 504 条计时、168 次检查，全部成功。矩阵名单、候选参数、输入与二进制哈希、原始日志、源码快照均归档。样本是机制分析用的已知案例，不是盲测或全库抽样。

## 4. 本轮消融结果

所有加速比均为“基线时间 / 变化后时间”。shape 和拆分两列是**同轮事后候选最优**，用于看候选覆盖，不是在线模型的实际收益：shape 比较“固定 32×1 普通”与“六种普通中最快”；拆分比较“六种普通中最快”与“六种普通+六种 balanced 中最快”。预取固定 shape/模式，先配对 12 种配置再取几何平均。

| 矩阵 | shape 候选覆盖 | 增加 balanced | depth=2 / 原内核 | 分组 / 同为32×1 |
|---|---:|---:|---:|---:|
| rajat09 | 3.631× | 1.000× | 1.041× | 回退 |
| poisson3Da | 3.081× | 1.000× | 1.025× | 回退 |
| FEM_3D_thermal2 | 1.000× | 1.000× | 1.034× | 1.764× |
| cop20k_A | 1.297× | 1.000× | 1.047× | 0.953× |
| mac_econ_fwd500 | 1.356× | 1.000× | 1.046× | 0.910× |
| pwtk | 1.338× | 1.029× | 1.014× | 1.346× |
| trans4 | 29.856× | 81.987× | 0.988× | 1.077× |
| webbase-1M | 5.934× | 5.950× | 1.016× | 1.236× |
| a5esindl | 20.471× | 11.902× | 0.971× | 0.799× |

长行案例中的巨大倍数是相对故意固定的低效普通路径：例如 trans4 的 balanced 候选扩展为 81.99×，不能当作相对 cuSPARSE 或原有自适应选择的加速比。

| 独立变化 | 本轮结果 | 解读 |
|---|---|---|
| 省去普通 32×1 的显式清零 | 9 张几何平均 1.054× | 小任务更明显；不是 balanced 可以免清零 |
| int16 对 int32 列号 | 2 张几何平均 1.000× | 省索引字节没有在这两个小例子上兑现稳定性能；通过增加未访问的零列强制 int32，双方 X 使用相同补齐分配，shape/实际访问不变 |
| 32×1 depth 4 对 depth 2 | 9 张几何平均 1.233× | 本组均更快；比较的是生产 tuned kernel 的批量深度，不代表其他 shape/硬件也适用，未改库默认 |
| balanced 32×1 CTA 合并 | 9 张 1.062×；3 收益、3 退化、3 基本持平 | 有效原子数、额外同步及 shared 开销共同决定 |
| cap 4 / cap 16 对 cap 8 | 9 张分别 0.895× / 1.014× | 任务数和长尾相互制约，不能仅凭 cap 大小决策 |
| 2 / 8 warp 对 4 warp | 9 张分别 0.980× / 0.979× | CTA 规模没有统一最优值 |
| 分组对未压缩 / 对旧逐 tile 压缩 | 实际启用 7 张分别 1.118× / 1.718× | 更容易超过旧动态解码；对未压缩仍有退化 |
| mixed 拆分 cap 8 对未拆分 | 9 张 2.622×；6 收益、2 退化、1 基本持平 | 长尾案例主导；拆分收益不能全部归给填充密度 |
| 最快 mixed(0/8) 对最快固定12配置 | 9 张 1.069×，5 收益、3 退化、1 基本持平 | 事后最优、固定仅 cap 8，不是公平覆盖所有 cap；已有 H100 80 张公平 cap 对照反而为 0.790× |
| DSM CSR 对两阶段 CSR | 固定 cluster=8，3 张 0.536×，全部更慢 | 该组不支持“DSM 必定更快”，也不是 DSM 指令对 atomic 的微基准 |
| DSM 长行+AtBSR 短行对原 AtBSR | a5esindl 1.191×；trans4 0.558×；webbase-1M 0.245× | 固定配置、未调优；仅在合适的长行结构/短行路径下获益 |

## 5. 与此前结果如何衔接

24 矩阵同卡对照保留原 shape/均衡选择，仅开启分组布局：全样本相对原 AtBSR 为 **1.089×**，实际启用的 16 张为 **1.142×**；全样本相对三种 cuSPARSE 中测得最快者仍为 **0.929×**。不能把本次故意覆盖长尾的 9 张机制样本当成这个更广样本的替代。

**分配与执行上下文仍是限制。** cop20k_A 在 24 矩阵/9候选实验及独立复测中开启分组约为 1.25×，本轮约 40 候选同时驻留时，同 shape 对照却为 0.953×。模型原选择和固定 32×1 对照本身也有差异；当前未定位到硬件根因。反序构建不能消除全部地址、缓存和 Graph 上下文影响，微小收益不应据此设为默认。mac_econ_fwd500 的分组退化则在多个批次重复出现。

已有 MFEM 大规模问题在双方关闭 L2 保留时，新布局内核 144.984 µs，原 AtBSR 171.008 µs，cuSPARSE DEFAULT 154.864 µs；八轮完整应用配对收益为 1.0199×（默认 CPU 调度）或 1.0231×（相同 CPU 绑定）。这是该应用的端到端结果，不推广到矩阵全库。已有 NCU 观察到分组相对旧压缩动态指令从 25,807,289 降到 15,184,402；但相对未压缩的 12,257,346 仍更多，支持“降低动态解码成本”，不支持“总比未压缩指令少”。本轮没有重采 NCU，不能据此为每张新矩阵定量归因。

应用优化另行归因：大 MFEM 原生后端仅结构复用就约为逐步重建参考的 1.659×；旧压缩的独立 2×2 消融并未证明完整应用稳定加速。L2 窗口也能帮助其他后端，不能计为六种 shape 的独有贡献。见 [应用](mfem-application.md)、[L2/旧压缩消融](mfem-column-ablation.md)、[新布局应用及指令证据](mfem-native-atbsr.md)。

统一选型模型、初始化调优和新分组布局不是同一个开关：分组目前未在已有预测模型中标定。此前 [选型快照](selection-model-current-snapshot.md) 的 2797 张合计 1.518× 来自两种不同选择流程，既不等于纯 AtBSR，也不包含本轮新分组收益；不能把它与 24 张的 0.929× 直接比较成版本退步或提升。

## 6. 当前可支持的结论

基础贡献是行长分组、shape/线程映射与长尾调度；分组索引进一步降低部分矩阵的解码和访存成本。混合 shape、DSM、预取深度和 CTA 参数均应作为有资格条件的候选，而不是全局固定开启。候选选择还需要考虑初始化、数值维护和预计调用次数，已有模型也不保证全局最优。

本报告已完成机制层消融和已有应用证据整理；没有宣称完成全库因子实验、跨架构泛化、冷缓存实验或对所有初始化/应用因素的完整析因。GPU 组装和 Graph 各自的独立收益本轮未重新消融，其组合流程与限制在应用报告中保留。

实验入口与原始数据结构见 [实验目录说明](../results/model/optimization-ablation/README.md)。算法流程见 [algorithm.md](algorithm.md)，统一接口见 [unified-mixed-plan.md](unified-mixed-plan.md)。
