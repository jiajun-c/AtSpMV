# 统一选型的特征统计优化

统一模型在 CPU 上为不同长行阈值提取统计。此前每个阈值都收集短行长度、排序，再计算六种 tile 的行组最大长度；大矩阵多次排序的代价较高。

对于可控的正阈值，短行长度落在 `[0, threshold)`，现在使用直方图按长度顺序计算排序后每组的最大行长，不必排序所有行。阈值过大、矩阵少于 512 行、或行数相对阈值太小时保留排序路径；没有短行时直接返回。行统计、每种 shape 的 tile 数和最大 tile 数保持一致。实现见 [hybridModelFeatures.h](../include/hybridModelFeatures.h)。

## 预测耗时

以下为 CPU 上直接调用 `choosePlanModel` 的合成基准：每种规模的 nnz 均不超过 H100 选择模型的 100 万上限，生成规则见 [selection_model_cpu_bench.cpp](../bench/selection_model_cpu_bench.cpp)。每个版本绑定同一 CPU 核，交替运行三轮，报告每轮平均时间的中位数。旧版使用排序提取特征；不包括读取矩阵、GPU 数据复制、AtBSR 打包、Plan 构造和 SpMV 执行。

| 合成矩阵行数 | 选型模式 | 旧版均值中位数 | 新版均值中位数 | 旧/新 |
| ---: | --- | ---: | ---: | ---: |
| 100 | 基础统一模型 | 7.45 μs | 8.88 μs | 0.84× |
| 100 | vector v2 | 38.37 μs | 37.61 μs | 1.02× |
| 10,000 | 基础统一模型 | 828.03 μs | 110.84 μs | 7.47× |
| 10,000 | vector v2 | 937.96 μs | 176.73 μs | 5.31× |
| 300,000 | 基础统一模型 | 17,549.4 μs | 1,295.13 μs | 13.55× |
| 300,000 | vector v2 | 19,817.9 μs | 2,011.01 μs | 9.85× |

这些数据只代表特定合成行长分布和机器上的 CPU 模型调用；小矩阵的基础模型在这次测量中慢约 1.43 μs。不能将其解释为完整 Plan 初始化或 GPU kernel 的加速比，也不能推断每张真实矩阵都会有同样的变化。原始计时与 medium-row 实验模式结果在 [结果目录](../results/model/selection-model/prediction-efficiency-v1/)。

## 验证

- [特征测试](../tests/hybrid_model_features_test.cpp) 对随机和边界行长、空行、组尾、12 个阈值，比较排序参考实现和优化实现的全部字段，包括 6 种 tile 的数量和最大值；非单调 CSR 偏移被拒绝。
- 364 张真实矩阵的主机端 medium-row 模型最终选型与旧回放一致，覆盖 254 张训练、72 张开发及 38 张保留样本；它们并非新盲测。
- H100 PCIe 上的 Plan 测试通过 952 项直接执行、Graph 和参考值检查；这验证的是测试覆盖内的数值正确性，不是完整数据集的性能实测。
