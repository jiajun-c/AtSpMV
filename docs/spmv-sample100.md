# 项目整理与 100 矩阵 cuSPARSE 对照

2026-11-11，本轮固定清单 **100/100 成功**，无丢弃或替换失败案例。相对每个进程中 cuSPARSE DEFAULT、CSR ALG1、CSR ALG2 的实测最快者，统一框架允许分组的几何加速比为 **1.295×**，72 个矩阵收益超过 1%、23 个退化超过 1%；中位加速比为 1.135×。这是分层选择的样本结果，不代表全库平均。

## 代码整理范围

- 将基准入口中的实验标签/选项映射抽到 [spmvBenchmarkOptions.h](../bench/detail/spmvBenchmarkOptions.h)，统一资源辅助放到 [spmvBenchmarkSupport.cuh](../bench/detail/spmvBenchmarkSupport.cuh)，行排序专用 packer 放到 [spmvRowOrder.cuh](../bench/detail/spmvRowOrder.cuh)。入口由整理前 223 行缩至 162 行，生产 API 不包含这些实验标签。
- 临时环境参数由作用域对象自动恢复，包括构建异常路径；六种分组 shape 的启动改为模板辅助函数，移除多行宏。没有修改数值计算、资格条件、默认开关或生产选择模型。
- 复用冻结 manifest 驱动，新增结构抽样、对照分析和审计入口；数据采集、统计和展示分离。实际 backend/config 保留在每进程原始 CSV，自动方案可以在不同进程选中不同配置。
- 进程监控改用可选 NVML 单设备查询，缺少模块时回退原查询；避免频繁启动全局 nvidia-smi。旧实验原始数据及其冻结驱动保留，没有删除历史研究代码。

## 测试设计

从本地结构清单固定种子抽取四个 nnz 档，每档 25 个；每档 13 个最长行小于 1024、12 个含至少 1024 非零元长行的矩阵，近似名称家族最多 3 个。限制 1000–2000 万 nnz、行列均不超过 200 万、有效实数/整数/pattern coordinate 输入；排除近期 24 个已反复分析的矩阵。只使用结构与输入头部取样，不按性能筛选，也不构成训练集外盲测。

同一 H100 PCIe GPU 3、FP64、两个独立进程反转构建顺序，9 轮随机交错计时，3 轮预热，每个 Graph batch 连续 8 次 SpMV，Graph 内 event 计时；prefetch=2、4 warp/CTA、cap=8，无 X 的 persisting L2 窗口，未锁时钟。报告先取每进程中位数，再对配对比值取几何平均。速度比不包含矩阵读取、转换、调优和 Graph 创建，属于重复执行的稳态结果。

统一框架配置为已有 Auto API 的 vector-v2 模型、有界初始化实测、五种 mixed 候选，并保留现有收益门槛。它不穷举所有 DSM、AtBSR 参数，不保证全局最优；模型范围外采用有界实测回退。“允许分组”只增加 AtBSR 候选采用分组列号的资格，不强制所有赢家使用分组内核。

## 整体结果

加速比 = cuSPARSE 时间 / 本方案时间，大于 1 表示更快。胜/负使用超过 1% 的界限，其余属于基本持平。

| 方案 | 相对最快 cuSPARSE | 相对 CSR ALG1 | 胜/负/持平 | Plan setup 中位数 |
|---|---:|---:|---:|---:|
| 原 AtBSR | 0.901× | 0.905× | 57/38/5 | 10.1 ms |
| 分组 AtBSR | 0.899× | 0.903× | 61/35/4 | 7.0 ms |
| 统一框架（v2+有界实测+mixed） | 1.287× | 1.292× | 71/26/3 | 116.0 ms |
| 统一框架允许分组 | 1.295× | 1.300× | 72/23/5 | 118.0 ms |

**主要收益来自选择后端，而非普遍开启分组。** 分组 AtBSR 相对原 AtBSR 仅为 0.998×，在这批样本没有整体收益；统一框架允许分组相对不允许为 1.006×，只是小幅差异，不能据此宣称稳健的额外提升。200 次含分组选项的原 AtBSR Plan 中 58 次实际启用；含分组选项的统一 Plan 中只有 15 次实际启用。默认开关保持关闭。

允许分组的统一框架在两个顺序共 200 次独立选择中，最终选中 AtBSR 73 次、CSR vector 66 次、mixed-tile 61 次。本轮没有选中 DSM 后端，不能据此宣称 DSM 没有有利场景；有界候选范围与样本结构都会影响选择。

setup 是各 Plan 构建/选择日志的描述性中位数，构建顺序、共享运行时预热和分配会影响它；不能通过上表相减把全部差异归因于布局。cuSPARSE 也预处理，但本基准未单列其 setup，因此不能据此声称单次调用或端到端总成本优于 cuSPARSE。统一方案的选型成本需要多次复用摊销。
