# 全部本地矩阵的混合 tile 性能与密度实验

`index.csv` 固定启动时在 `/staff/chengjiajun/workspace/database/suitsparse` 发现的 2,888 个 `<name>/<name>.mtx` 矩阵，按照 Matrix Market 头部估算的展开非零元数由小到大运行。稀疏对称格式的展开估算是原记录数的两倍上界，不是精确 nnz。默认 GPU 是 1 号 RTX 5880 Ada，不可将性能结论推广到 H100。

每张矩阵比较同一混合布局的 5 个执行方案与 AtBSR 的 24 个固定 shape/负载均衡/切分大小候选，另记录默认 AtBSR。每个候选两组向量做直接正确性检查，第二组做 CUDA Graph 检查；预热后随机交错计时，每次图内含 8 次调用，9 次测量取中位数，两个进程使用相反的候选构建顺序。报表逐顺序使用事后最快候选，故不等同于当前选择模型的实际选择。密度定义为 nnz / 所有 tile 槽数，与元数据占用分开；时间不包含预处理或实际选型。

单矩阵状态记录在 `status/`，原始计时、校验日志在 `raw/`。机器上其他任务使用该 GPU 时停止当前样本、放弃其数据并等待后重试；采样式检查不能消除所有干扰。脚本设置每矩阵 600 秒超时；格式不支持、CUDA 内存不足、超时、数值错误等均记录为失败而不混入汇总。为避免不受控的超大输入，若展开 nnz 的上界达到 int32 上限，或按 `64 × (展开 nnz 上界 + 行数)` 的粗略主机内存估计超过 64 GiB，则记录 `resource_limit`，不会在本次运行尝试。启动时清单中有 12 个矩阵触发这个保护；实际内存消耗不能由此公式精确预测。这些矩阵仍然列在完整清单里，不能把本次结果称为全部矩阵均已成功测试。

任务由独立 `tmux` 会话 `atspmv_mixed_all` 执行，VS Code/SSH 断开不影响；服务器重启或 tmux 服务终止不在此保证范围内。已完成矩阵的状态会保留，重新运行 `run.sh` 从状态目录继续；不要同时启动两个实例。每次查看：

```bash
results/model/mixed-tile/all-2888-ada/status.sh
# 或查看实时日志
 tail -f results/model/mixed-tile/all-2888-ada/runner.log
```

`status.sh` 会更新 `analysis.csv`、`analysis.json` 和 `live-summary.log`。按规模排序意味着中途统计偏向小矩阵，不能当作最终总体结果。完整运行后 `summary.log` 保存最终统计；即使没有成功完成全部矩阵，失败和资源限制也会单独计数。
